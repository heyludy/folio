# 자료량과 게시 흐름 개선

## 디자인 계획

- 기존 교수님 페이지의 네 디자인과 글꼴을 유지한다. 긴 문장은 읽는 폭에 맞춰 줄바꿈하고, 사진 없는 공간은 본문에 돌려준다. 논문을 숨기거나 글씨를 과도하게 줄이지 않는다.
- 관리 화면 색: 흰색 #ffffff, 옅은 회색 #f7f9f8, 차콜 #2a2a2a, 그린 #355b49, 구분선 #dfe3df, 변경 안내 #805d20. 관리 글꼴은 Pretendard.
- 게시 완료: 공개 주소를 먼저 보여주고 바로 아래에 [사이트 열기] [주소 복사] [도메인 연결]을 묶는다. 이미 도메인이 있으면 관리로 연결한다.
- 편집기: 프로젝트명 / 게시 상태 → 미게시 변경 안내 + 게시 버튼 → 편집 영역. 저장 진행 중과 저장 완료를 구분한다.
- 검토: 장식이나 기능을 더하기보다 담당자가 “지금 공개된 내용인지”와 “다음에 누를 버튼”을 알도록 한다. 첫 게시가 진행 중인 경우 완료 화면을 보여주지 않는다.

## QA 범위

긴 영문 이름과 소속, 긴 한글 소속, 공백 없는 문자열, 사진 없음, 논문 30개, 영어만 구성한 자료를 네 템플릿과 320–1440px 화면에서 확인한다. 실제 교수님 프로젝트 대신 별도 예시 자료를 사용한다.

## 반영한 내용

- 기본형·연구형의 모바일 소개에서 소속은 사진 옆 좁은 칸 대신 다음 줄 전체 폭으로 표시한다.
- 사진 없는 소개문과 컬러형 소속은 읽는 폭을 제한한다. 사진 없는 템플릿과 적은 자료도 별도 빈 사진 칸 없이 구성한다.
- 게시 완료 후 사이트 열기·주소 복사·도메인 연결을 묶고, 복사 결과는 누른 버튼에 바로 표시한다. 연결된 도메인은 도메인 관리로 진입한다.
- 완료된 화면에서 비활성화된 게시 버튼과 이전 비교 설명을 제거한다. 재게시 중에는 기존 공개 주소임을 안내한다.
- 편집기와 프로젝트 카드에서 저장된 수정사항이 아직 공개되지 않았음을 표시한다. 저장 중·저장 실패 상태는 저장 완료로 표현하지 않는다.

## 확인 결과

- 네 템플릿 × 자료 3종 × 언어 × 320/390/600/768/1024/1440px, 총 96조합에서 넘침 없이 표시. 논문 30개 모두 접근 가능, 헤더 고정 유지.
- 사진 없는 컬러형과 긴 이름·소속의 모바일 기본형을 시각 점검.
- 로컬 가상 게시 서버로 첫 게시 → 처리 중 → 완료, 수정 후 재게시, 이미 연결된 도메인, 게시 실패를 확인. 실제 교수님 홈페이지를 재게시하지 않았다.
- 완료 화면에 세 버튼 표시, 주소 복사 피드백, 도메인 입력/기존 도메인 관리 경로 확인. 390px에서도 버튼과 주소가 잘리지 않음.
- 저장 중·저장 오류에서 게시 버튼 비활성화 확인.

재현: `npm test` 후 `node scripts/build-content-stress.mjs` → 로컬 preview의 `/qa-content/`에서 Run matrix. 게시 흐름은 Vite 개발 서버의 `/scripts/publish-flow-qa.html`에서 확인한다. 두 도구 모두 가짜 QA 자료를 사용하며 배포 빌드에는 포함되지 않는다.

최종 검사: 앱 218개 + 게시 서버 12개 통과. 배포 빌드와 Worker 사전 검사 통과.

## 발견한 문제와 수정

### 1. 연구형 소개가 화면 가장자리에 붙음

연구형이 기본 소개의 음수 좌우 여백을 물려받은 상태에서 안쪽 여백만 제거해, 이름과 본문이 화면 끝에 붙었다. 연구형 소개의 바깥 여백을 초기화했다.

- 390px 공개 미리보기에서 이름의 왼쪽 여백: **0px → 22px**
- 긴 자료 검사에 연구형 이름의 최소 좌우 배치 여백 확인을 추가했다.
- 편집 화면과 HTML 출력이 같은 스타일을 사용한다.

### 2. 브라우저 저장 충돌 중 게시·초안 공유 가능

공용 저장 모드와 달리 브라우저 저장 모드는 상단 게시 버튼과 미리보기의 초안 공유 버튼이 저장 완료를 기다리지 않았다. 두 버튼 모두 저장 완료를 확인하도록 통일했다.

재현·재검증: 같은 로컬 프로젝트를 두 탭에서 열어 동일 소개문을 각각 수정했다. 먼저 저장한 내용은 유지되고, 나중 탭은 충돌 안내와 함께 게시·초안 공유가 비활성화된다. ‘최신 내용 열기’로 먼저 저장한 내용을 복구했다.

## 운영 확인 및 범위

- 운영 Folio, 네 템플릿 예시, `heoe.info`, 힌턴 예시의 공개 사이트가 브라우저에서 정상적으로 열렸다.
- 기존 Google 로그인 세션과 서버의 계정·공용 저장소 연결을 확인했다. Google의 새 계정 선택·동의 절차를 다시 수행하지는 않았다.
- 실제 교수님 프로젝트를 수정·복원·삭제하거나 홈페이지를 재게시·중단하지 않았다. 공개 상태를 바꾸는 검사는 가상 서비스와 Worker 테스트에서 실행했다.
- 운영 사이트는 최신 편집기 디자인과 별도로 마지막 게시 버전을 유지하며, Folio에서 ‘디자인 반영 필요’로 안내하고 있다.
- 모바일은 브라우저의 화면 너비로 검사했다. 실제 iPhone Safari·Android 기기의 터치·다운로드 동작은 별도 기기 확인 범위다.
- 다운로드 HTML은 공개 결과물이다. 편집용 프로젝트를 파일로 백업하고 다시 가져오는 기능은 현재 없으며, 클라우드 저장·수정 이력 복원·프로젝트 복제를 제공한다.
- 빌드의 큰 번들 경고는 남아 있다. 다음 성능 개선 후보는 편집기·HTML 생성·예시 자료의 분할 로딩이다.

## 재현

```sh
npm test
npm run test:worker
npm run publisher:check
npm run build
node scripts/build-content-stress.mjs
node scripts/build-section-fixtures.mjs
```

- 긴 자료 검사: 로컬 preview의 `/qa-content/` → Run matrix.
- 전체 섹션 검사: `../outputs/section-designs/index.html`을 로컬 서버에서 열어 Check all sections.
- 가상 게시·초안 공유: Vite 개발 서버의 `/scripts/publish-flow-qa.html`. `127.0.0.1` 개발 환경에서만 동작하며 실제 배포를 만들지 않는다.
- 브라우저 저장 검사: Supabase 환경 변수를 비운 별도 로컬 서버에서 합성 테스트 프로젝트를 사용한다.
- 기존 섹션·템플릿 검사 도구의 오래된 템플릿 목록을 현재 설정에서 읽도록 수정했다. 기본형·소개형·컬러형·연구형이 모두 검사된다.

## GitHub 저장 범위

소스 코드, 자동 검사, QA 기록은 `heyludy/folio`의 `main`에 커밋·푸시한다. GitHub Actions가 검사와 빌드 후 관리자 Folio를 GitHub Pages에 배포한다. 교수님별 편집 데이터는 공용 클라우드 저장소에 저장되며 Git 커밋 대상이 아니다.

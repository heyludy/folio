## 새 프로젝트 순서·줄바꿈 수정

사용자 스크린샷의 언어 라벨 세로 줄바꿈은 일반 텍스트 입력칸의 `width: 100%`가 라디오에도 적용되어 발생했습니다. 텍스트 입력 스타일에서 라디오·체크박스를 제외하고, 깨진 간이 언어 선택을 없앴습니다.

- 새 프로젝트: 템플릿 → 언어 → 기본 정보 → 자료 준비 순서로 복원
- 기존 프로젝트의 ‘기본 정보’는 기존처럼 바로 입력 화면 열기
- 한국어 안내 문구는 단어 단위로 줄바꿈, 언어명은 한 줄 유지
- 템플릿 설명을 줄이고 제목·상태 배지가 각각 배치될 공간 확보

브라우저에서 각 단계와 뒤로 이동 후 입력 보존, 생성 후 자료 준비, 기존 정보 수정까지 확인했습니다. 템플릿 대화상자 720px에서 네 설명은 각각 한 줄이며, 언어 라디오의 실제 너비는 15px이고 두 언어 라벨도 한 줄입니다. 세 화면을 스크린샷으로 확인했고 기존 73개 검사와 빌드가 통과했습니다.

1. AI 답변의 Markdown 코드 블록 뒤 설명이 마지막 공개 필드에 붙던 문제: 코드 블록 바깥 문장은 제외하고, 지원하지 않거나 끝나지 않은 블록은 안내합니다. 여러 Markdown 블록과 EN/KO 구분은 유지합니다.

## 테마 색상·프로젝트 삭제

모든 테마가 같은 배경색을 쓰던 구성을 바꾸고, 테마별 밝은 배경과 소개·연락처의 색면, 이름·제목·언어 버튼의 포인트색을 적용했습니다. 프로젝트 카드와 색상 선택기의 미리보기도 같은 색상 조합을 사용합니다.

프로젝트 카드에 삭제 버튼을 추가했습니다. 삭제한 프로젝트는 홈의 접힌 목록에 보관하며 즉시 되돌리거나 새로고침 후 복원할 수 있습니다. 프로젝트 ID와 사진·PDF·자료 준비 초안을 유지합니다.

자동 검사 89개 통과, 배포 빌드 성공. 삭제·복원 데이터 보존, 마지막 프로젝트 삭제, 다른 탭 수정과의 병합, 테마별 글자 대비 검사를 추가했습니다.

로컬 브라우저에서 확인한 항목:

- 다섯 테마의 배경·소개 영역·이름·제목·연락처 색상이 각각 적용됨
- 카드 삭제 버튼이 프로젝트 열기와 독립적으로 동작
- 즉시 되돌리기, 삭제된 목록의 새로고침 후 유지와 복원
- 모든 프로젝트 삭제 후 프로젝트 0개 표시, 새 프로젝트 생성 완료
- 삭제한 프로젝트는 편집기의 사이트 선택 목록에서도 제외
- 복원한 프로젝트의 영·한 내용, 사진, CV PDF, 폰트와 테마 보존
- 실제 내려받은 HTML의 새 색상 적용과 320·390·768·1440px에서 가로 넘침 없음
- 테스트 중 브라우저 오류·경고 없음

## Google 로그인·공용 프로젝트 (연결 전 검증)

- 확인된 Google 이메일과 정확한 허용 도메인을 검사한다. 사용자 편집 가능 metadata, 미확인 이메일, 비슷한 도메인은 거절한다.
- PostgreSQL 호환 환경에서 서비스 전용 접근 권한, 공용 revision 충돌, 게시 ID 유지, 가입 허용 목록을 검사했다.
- 사진/PDF 중복 저장 방지, 다른 필드 병합, 같은 필드 충돌 보존, 오프라인 임시본 복구를 검사했다.
- 로컬 가짜 OAuth·API 서버로 로그인 → 프로젝트 생성 → 저장 → 두 번째 탭의 동일 프로젝트 → 암호 없는 게시 설정 → 로그아웃 흐름을 확인했다. 실제 Google 인증 검증은 Supabase 연결 후 진행한다.
- Workers의 `redirect: 'error'` 미지원 문제를 발견해 `manual`로 수정했다. 리디렉션을 따라가지 않으며 성공 응답만 처리한다.
- 자동 검사 148개, Workers 실행 검사 5개 통과. 게시 서버 dry run 및 프런트 빌드 통과.
- Supabase와 Google OAuth 연결 전까지 클라우드 모드는 비활성 상태로 유지한다.

## 허은녕 상세 콘텐츠 초안

- 영문·한글 각각 12개 영역, 목록 항목 26개를 MD로 작성했다. 파서에서 경고 없이 24개 언어별 영역을 읽었다.

- 미리보기의 중복 학력 본문을 제거했다. 언어 전환, 이메일·논문 링크, 데스크톱 및 320/390/768px 미리보기를 확인했다.

## Google 로그인·공용 저장 운영 전환

- Google OAuth 웹 클라이언트와 Supabase Google 제공자를 연결하고 OAuth 앱을 프로덕션 상태로 전환했다. 요청 범위는 기본 프로필·이메일·openid다.
- 두 등록 관리자 계정으로 실제 Google 로그인에 성공했다. 첫 계정에서 저장한 초안을 두 번째 계정에서 열고 수정·저장했으며, 테스트 값은 원래대로 복원했다. 실제 에이퍼브 구성원 계정 로그인은 미검증이며 허용 도메인·차단 목록은 자동 검사로 확인했다.
- 기존 브라우저 프로젝트 3개와 사진을 공용 공간에 가져왔다. 허은녕 프로젝트의 기존 게시 ID와 `heoe.info` 연결을 유지했다. Google 로그인 상태에서 도메인 설정이 별도 암호 없이 열리고 HTTPS 연결 완료를 표시한다.
- 가져오기 버튼의 겹침, GitHub Pages OAuth 복귀 주소, 브라우저에 남은 옛 게시 ID가 공용 연결보다 우선하던 문제를 수정했다.
- 실제 Supabase Storage가 중복 사진에 HTTP 400 / `statusCode: 409` / `KeyAlreadyExists`를 반환해 재저장이 실패하는 문제를 수정했다. 새로 연 세션에서 기존 사진을 포함한 초안 재저장·재열기를 확인했다.
- 자동 검사 166개와 Workers 실행 검사 7개, 게시 서버 dry run, GitHub Pages 배포가 통과했다. 교수님 공개 콘텐츠는 변경하지 않았으며 `https://heoe.info/` HTTP 200을 확인했다.
- 운영 사이트는 `CLOUD_ENABLED=true`다. 이전 게시 암호 세션은 차단하고 Google 세션으로 공용 프로젝트 권한을 확인한다. 프런트엔드에는 공개용 Supabase 키만 포함한다.
